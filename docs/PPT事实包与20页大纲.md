# 一、事实包（唯一可引用来源）

## 1.1 一句话定位

云镜推演是面向云原生系统的故障推演与恢复决策沙盘：先把系统装配出来判断能不能跑，再注入故障推演会波及谁、多久到，最后比较恢复方案，回答先救谁、救完会不会更糟。

边界：不接入生产监控、不执行真实故障注入；恢复时间/成本/风险为模型估算；基础算法（BFS、割点、加权评分）为成熟方法，创新在建模粒度、组合方式与决策表达。

## 1.4 算法与公式

传播（E1）：多源反向 BFS，O(V+E)；强度 = 边权累乘 × 容量放大 × 依赖冗余度。

容量放大 = 1 + 0.5 × 宿主 CPU 利用率（最高 1.5 倍）。

依赖冗余度 r = 受影响下游依赖数 / 总下游依赖数；强度 × r，阈值 0.6 判「必崩」，否则「可能」。

时间窗：到达时间 = 路径上 latency_ms 之和，可只算 T 秒内的波及范围。

恢复评分 = 100 × (0.25×时间分 + 0.20×影响分 + 0.15×成本分 + 0.20×风险分 + 0.20×业务恢复分)；时间分 = max(0, 1−耗时/600s)。

隔离折扣：隔离不恢复业务，业务恢复分 ×0.6，避免靠「快」永远第一。

级联：容量 = cpuCores 或 cpuRequest；基线负载 = 0.6×容量；故障负载转移给优先级最高的备用；接管后负载 > 容量即过载，最多 6 轮。

## 1.5 十二条校验规则

| 编码 | 规则 | 级别 | 判定 |
| --- | --- | --- | --- |
| R01 | 端口冲突 | 错误 | 同节点 (协议,端口) 重复；同宿主 public 宿主端口重复 |
| R02 | 端口越界 | 错误 | 端口不在 1–65535 |
| R03 | 端口映射冲突 | 错误 | port_map 目标非宿主机，或宿主端口冲突 |
| R04 | CPU 超配 | 错误 | 宿主上 cpuRequest 之和 > cpuCores |
| R05 | 内存超配 | 错误 | memRequest 之和 > memTotalMb |
| R06 | 磁盘超配 | 错误 | diskGb 之和 > 宿主磁盘 |
| R07 | 依赖缺失 | 错误 | 接口级依赖缺端口；服务沿依赖链到不了中间件/对象存储 |
| R08 | 网络不可达 | 错误 | 跨宿主调用无网络路径（外部系统、未部署节点除外） |
| R09 | 循环依赖 | 错误 | depends_on 有环 |
| R10 | 入口不可达 | 警告/错误 | 无入口时警告；有入口但服务不可达时报错 |
| R11 | 孤儿节点 | 提示 | 节点没连任何线 |
| R12 | 主备不完整 | 警告 | 缺主/缺备/端口不一致/备用不可用 |

# 三、视觉规范（让 PPT 不像 AI 做的）

| 项 | 规范 |
| --- | --- |
| 画幅 | 16:9（1920×1080） |
| 底色 | #0B1220 深蓝黑，内容区可加 #0F172A 卡片 |
| 主色 | #38BDF8 青蓝，辅助 #A78BFA 紫、#F59E0B 橙 |
| 文字 | 标题思源黑体 Bold 36–44pt；正文 20–24pt；最小不小于 18pt |
| 版式 | 每页一个大标题 + 一句结论 + 三块内容；留白 ≥ 20% |
| 配图 | 只用真实截图与自绘图表，禁止 AI 生成配图、禁止图库风景图 |
| 图表 | 条形/雷达/流程图优先；数字大字号，单位清晰 |
| 动效 | 只保留「逐条出现」和「数字滚动」，不加翻页转场 |
| 禁忌 | 大段文字、渐变紫、无意义图标、英文缩写不解释、假数据 |

视频里说的「去 AI 味」，核心就三条：真实素材、具体数字、短句。每页只讲一个观点，能用图就不用字。

# 四、给 GPT 的提示词模板（复制即用）

第一段（角色与约束）：

你是挑战杯答辩 PPT 设计顾问。下面给你《事实包》和《20 页大纲》，请严格基于它们工作：1）只能引用事实包里的数字，禁止编造；2）每页标题 ≤12 字，下面一句「所以呢」≤30 字；3）每页给 3 个要点 + 至少 1 个数字；4）标注该页用图类型（截图/流程图/对比表/数字卡片）；5）每页给 60 字以内口播稿；6）风格深色科技，主色 #38BDF8，16:9，正文不小于 20pt。

第二段（产出格式）：

请按页输出：页码｜标题｜结论句｜三个要点｜关键数字｜配图建议｜口播稿。不要写「欢迎来到」「让我们」这类空话，不要用感叹号。

第三段（迭代）：

先只输出 20 页的标题和结论句让我确认结构，确认后再逐页展开；每 5 页停下来等我反馈。
